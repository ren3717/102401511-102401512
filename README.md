# 校园失物招领（Campus Lost & Found）

> 2026 秋 软件工程与软件工程实践 —— 第二次结对作业（程序实现）
>
> 结对成员：**何锦宏（102401511）**、**任奥辉（102401512）**

一个面向校园场景的失物招领 Web 应用：把分散在班级群、宿舍群、朋友圈里的寻物与招领信息集中到一处，
支持发布、浏览、搜索、查看详情、联系发布者，并在物品找回或归还后由发布者更新信息状态，
减少重复询问和无效联系。

---

## 一、如何运行（测试人员请看这里）

**不需要安装任何环境、不需要联网、不需要启动服务器。**

1. 把本项目所有文件下载到本地（保持目录结构不变）
2. 用 **谷歌浏览器（Chrome）** 打开 `index.html` 即可

> 说明：本项目为纯静态网页（HTML + CSS + 原生 JavaScript），所有数据保存在浏览器本机
> （localStorage），因此不需要 Node.js、npm、数据库或后端服务。
> 首次打开时会自动载入 10 条演示数据，方便直接体验浏览与搜索。

### 建议的体验顺序

| 步骤 | 操作 | 对应功能 |
| ---- | ---- | ---- |
| 1 | 打开 `index.html`，浏览信息卡片，切换「全部 / 寻物 / 招领」，使用分类、地点、状态筛选 | 浏览与筛选 |
| 2 | 在顶部搜索框输入「校园卡」回车 | 关键词搜索 |
| 3 | 在结果页点击任意卡片的「查看详情」 | 查看详情 |
| 4 | 在详情页点击「📋 复制联系方式」 | 联系发布者 |
| 5 | 点击右上角「＋ 发布信息」，填写表单后提交 | 发布信息 → 发布成功 |
| 6 | 进入「我的发布」，点击「✓ 标记为已找到 / 已归还」 | 更新状态 |
| 7 | 回到首页，可以看到该条信息的状态已同步变化 | 状态同步 |

### 运行单元测试

用 Chrome 打开 `tests/test.html`，页面会自动运行全部单元测试并显示结果
（共 **117 个用例、25 个测试分组**，正常情况下应全部为绿色 ✓）。

### 代码组织思路

- **逻辑与界面分离**：`store.js` / `utils.js` 是纯逻辑，不接触页面 DOM。好处是它们
  可以脱离浏览器直接做单元测试，也方便以后替换数据源（例如换成后端 API）。
- **公共部分抽取**：导航栏、页脚、信息卡片、提示框都放在 `ui.js`，避免 6 个页面重复实现。
- **零第三方依赖**：不使用 jQuery / Vue / Bootstrap 或任何 CDN 资源，
  保证"下载后双击就能跑"，不会因为断网或版本变化导致页面打不开。

## 三、功能清单

**基础功能（作业要求）**

- 浏览失物与招领信息（首页信息流，按类型分类查看）
- 发布寻物信息 / 发布招领信息（同一表单，切换类型）
- 关键词搜索（匹配物品名称、描述、地点、分类名，命中文字高亮）
- 查看物品详情（图片、地点、时间、描述、发布者与联系方式）
- 联系发布者（一键复制联系方式）
- 修改信息状态（发布者标记为「已找到」或「已归还」）

**附加特点**

| 特点 | 说明 |
| ---- | ---- |
| 多维筛选 | 按分类（卡证/生活用品/数码电子/书籍/衣物/其他）、地点、状态组合筛选 |
| 一键复制联系方式 | 详情页点击即复制到剪贴板，失败时自动回退到兼容方案 |
| 搜索历史 | 自动记录最近 6 个搜索词，保存在本机，可一键清空 |
| 关键词高亮 | 搜索结果中命中的文字用黄色底纹标出，便于快速定位 |
| 图片压缩上传 | 照片在浏览器端用 canvas 压缩到最长边 900px 再保存，避免撑爆存储 |
| 状态同步说明 | 信息结束后显示提示条，明确告知"谁改的、在哪看"，避免重复联系 |
| 空状态与错误提示 | 无结果、无发布、表单填写不完整都有明确提示与引导按钮 |
| 数据容错 | 本地数据损坏、存储写满、禁用本地存储等异常都不会导致页面崩溃 |
| 响应式布局 | 桌面端三列卡片，窄屏自动降为单列，手机上也能正常使用 |
| 恢复演示数据 | 「我的发布」页提供一键恢复演示数据，便于反复测试 |

## 四、单元测试说明

| 项目 | 内容 |
| ---- | ---- |
| 测试框架 | 自研 `tests/mini-test.js`（约 120 行，零依赖，双击 `tests/test.html` 即运行） |
| 用例数量 | 117 个用例 / 25 个测试分组 |
| 覆盖范围 | `js/utils.js`（工具函数）、`js/store.js`（数据层） |
| 设计方法 | 等价类划分 + 边界值分析 + 特殊值（空值、非法值、损坏数据、存储异常） |
| 隔离手段 | 测试使用内存假存储（Test Double），不读写真实数据，可反复运行 |

测试曾经发现并修复了两个真实缺陷：

1. `genId()` 在同一毫秒内连续生成 1000 个 ID 时出现重复 —— 原因是随机部分只有 4 位，
   加入自增序号并加长随机串后解决；
2. 同一毫秒内发布的多条信息 `createdAt` 相同，导致"按发布时间排序"结果不稳定 ——
   改为在新增时保证时间戳严格递增。

## 五、已知限制

- 数据保存在浏览器本机，换一台电脑或清除浏览器数据后信息会消失（本项目不使用服务器）
- "我的发布"依据"是否在本机发布"判断，没有账号体系（作业明确不要求实名认证与后台管理）
- 图片以 base64 形式存放在 localStorage，容量有限（浏览器通常约 5MB），
  因此已限制最多 3 张并对图片做压缩；存储写满时会给出明确提示
